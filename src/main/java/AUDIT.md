## Правила для будущих изменений

1. **Не рефакторить соседние методы «заодно».** Если патч трогает
   `doUpgrade`, не переносить заодно `finishUpgrade`. Один коммит —
   одна задача.
2. **Не менять публичные сигнатуры** без отдельного этапа и явного
   согласования. Второй ИИ/ревьюер не должен «улучшать» API.
3. **Менять by-design поведение** — только с явной ссылкой на запрос
   геймдиза/владельца. Не «потому что так чище».
4. **Все by-design решения помечены в коде** тегом `AUDIT-BY-DESIGN`.
   Ищите по проекту: `grep -rn "AUDIT-BY-DESIGN" src/`.

## By-design решения (НЕ БАГИ)

| # | Место | Что происходит | Почему так |
|---|-------|----------------|------------|
| 1 | `RewardService.giveCityRewards` | При переполнении `/t stock` предметы теряются, часы не возвращаются | Игрок получает монеты всегда (основной канал). Частичный refund по предметам = race window с `consumeCityHours`. |
| 2 | `RewardService.givePlayerRewards` | Если у города нет `city_bank` (или lvl 0) — часы игрока сгорают | Иначе «вечный банк часов»: копить без здания → построить → получить всё сразу (500/ч × 720 = 360k). Ломает баланс. |
| 3 | `BuildingService.tryUpgrade` (safety-timeout) | При успехе апгрейда после 30-сек таймаута игрок видит TIMEOUT, но уровень уже повышен | Не дюп и не потеря: заплатил → получил. Доп. уведомление после TIMEOUT = спам в момент, когда игрок уже отвлёкся. CAS в БД защищает от повторного апгрейда. |
| 4 | `DatabaseManager.disconnect` | 5-сек drain для `pendingOnStop`; при медленной БД часть «хвостовых» задач теряется | Игровые данные защищены отдельными флашами ДО `disconnect`. 5 сек — компромисс между «успеть» и «не вешать shutdown». |

## Известные ограничения (не баги, но знать надо)

- **`folia-supported: false`** в `paper-plugin.yml`. Код местами использует
  `Bukkit.getScheduler()` (Folia-несовместимо), местами —
  `GlobalRegionScheduler`. На Folia работать не будет. Если нужно — отдельный
  этап миграции, не «попутно».
- **`WonderService.timedProgress`** — in-memory аккумулятор `timed-items`.
  Сбрасывается при рестарте сервера. Осознанно: персистить = отдельная
  таблица + атомарные апдейты на каждый час. Не «оптимизировать» в
  in-memory вариант без запроса.
- **`BlockPlaceTracker`** — bounded map с `MAX_ENTRIES`. При переполнении
  `clear()` теряет трекинг всех блоков (бонусы за player-placed блоки
  не срабатывают ближайшие TTL-минуты). Так лучше, чем OOM.

## Отложенные фиксы (этапы 3-4 аудита)

См. отдельные коммиты `audit/3: ...`, `audit/4: ...`. Пока НЕ реализованы:

- chunkBonus: порядок Towny → БД при reconcile (сейчас: БД → Towny).
- Wonder admin vs player: общий `inFlight` per town.
- `BonusService.scheduleRefresh`: переиспользовать `winner`.
- `BranchMenu`: кэш `countAll` с TTL.
- `MessagesConfig.get(key)` без placeholders: bounded LRU.
- `DatabaseManager`: `ioThreads` 4 → 8, queue 500 → 2000, bounded `pendingOnStop`.
